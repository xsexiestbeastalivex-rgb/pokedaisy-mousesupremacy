# Upstream architecture audit

The fork's `main`, upstream `main` and the peeled upstream tag `v1.6.2.1` were all at [717f4f49979f4aa5c4c8f4cd64638a0fa935d844](https://github.com/lidor30/pokedaisy/commit/717f4f49979f4aa5c4c8f4cd64638a0fa935d844) during initialization. The annotated tag object is `a192bd1fbc7b161a11f2a31ba501fff8c15ae334`. The fork and upstream share the commit and tree, so one source audit covers both. Source links refer to that baseline and line numbers can drift after an upstream sync.

This page records source findings and a small fixture inspection. Build and runtime evidence is reported in [project status](PROJECT_STATUS.md). Existing upstream convenience actions often use mechanics inappropriate for MouseSupremacy. Their layout knowledge, observation and scheduling remain useful.

## Application, input and emulation

| Area | Confirmed in source | Implication and remaining proof |
| --- | --- | --- |
| Android host | [PokeDaisyActivity](../../app/src/main/kotlin/com/pokedaisy/app/PokeDaisyActivity.kt) owns app lifecycle, windows, controller/touch input and companion composition. [EmulatorEngine](../../app/src/main/kotlin/com/pokedaisy/app/EmulatorEngine.kt#L1316) drives frame, script, telemetry and render work. [GameSession](../../shared/src/commonMain/kotlin/com/pokedaisy/app/game/GameSession.kt) owns between-frame work and field-job lifecycle. | Add ownership at the existing Android input/frame boundary. Pin the order of physical masks, script work, observing and committing a key. |
| Native core | [pk_api.h](../../app/src/main/cpp/pk_api.h) and [pk_session.c](../../app/src/main/cpp/pk_session.c) expose core lifetime, keys, frame, memory, saves and render. [JNI](../../app/src/main/cpp/pokedaisy_jni.c) wraps GBA/GB and dispatches DS separately. [CMake](../../app/src/main/cpp/CMakeLists.txt) builds mGBA, rcheevos and integrated DS code. [NDK pins](../../app/build.gradle.kts) and [submodules](../../.gitmodules) define build inputs. | Drive the existing key interface. Define a small coherent read for action readiness. Keep production free of general diagnostic memory control. |
| Shared code | Root [source lists](../../build.gradle.kts) and [shared](../../shared/build.gradle.kts)/[shared-ui](../../shared-ui/build.gradle.kts) compile reused codecs, companion logic and UI that often still live under `app/src/main/kotlin`. iOS [PkApiCore](../../shared/src/iosMain/kotlin/com/pokedaisy/app/core/PkApiCore.kt) drives the C API. [Desktop preview](../../ui-preview/README.md) uses JVM shims. | Pure interaction logic can migrate through established shared boundaries. Compose preview verifies composition in a separate host without Android input or native core execution. |
| Native alternatives | [Linux SDL](../../linux/main.c) hosts libretro cores. [Windows instructions](../../docs/manual/windows-install.md) describe the desktop packaging. [3DS port](../../3ds/README.md) has its own C paths and core choices. | Android behavior and platform feature parity require separate verification. Native Windows/SDL is a future host option through a reused contract. |
| Input routing | [Activity key dispatch](../../app/src/main/kotlin/com/pokedaisy/app/PokeDaisyActivity.kt#L5321) and [generic motion](../../app/src/main/kotlin/com/pokedaisy/app/PokeDaisyActivity.kt#L5744) handle keys and joystick motion. [AndroidGbaInput](../../app/src/main/kotlin/com/pokedaisy/app/AndroidGbaInput.kt) maps controllers. [TouchInputWindows](../../app/src/main/kotlin/com/pokedaisy/app/TouchInputWindows.kt#L94) consumes events in transparent touch-control subwindows. Source investigation found no native mouse hover route. | Probe Android callbacks, breaks around the first click, duplicate button paths and actual WSA source/action fields. Child/subwindow ownership and platform Back require physical evidence. |
| Key scheduling | [GbaInput](../../app/src/main/kotlin/com/pokedaisy/app/GbaInput.kt#L133) combines physical, script and queued tap sources. [ScriptInput](../../app/src/main/kotlin/com/pokedaisy/app/ScriptInput.kt) reads/writes the script mask. [EmulatorEngine](../../app/src/main/kotlin/com/pokedaisy/app/EmulatorEngine.kt#L1358) combines frame key sources before the core. [ManualInputGate](../../shared/src/commonMain/kotlin/com/pokedaisy/app/game/ManualInputGate.kt) illustrates owner flags, used by [iOS input](../../shared/src/iosMain/kotlin/com/pokedaisy/app/game/GameInput.kt). | Android companion ticks can replace the script mask. A second producer that writes the same mask would race. One frame owner must protect synthetic edges and preserve genuine held buttons. |

## Identity and native battle

| Area | Confirmed in source or fixture | Implication and remaining proof |
| --- | --- | --- |
| ROM identity | [RomIdentity](../../app/src/main/kotlin/com/pokedaisy/app/RomIdentity.kt), [RomIdentityReader](../../app/src/main/kotlin/com/pokedaisy/app/companion/data/RomIdentityReader.kt), [Poller](../../app/src/main/kotlin/com/pokedaisy/app/companion/data/Poller.kt#L1082) and [generated configurations](../../gamedata/README.md) support exact IDs and broad/derived engine inference. Upstream's [ROM features](../ROM_FEATURES.md) describe existing support. | Adopt the unmasked whole-file identity for initial qualification. The [bus digest](../../app/src/main/kotlin/com/pokedaisy/app/companion/data/Poller.kt#L1455) normalizes RTC/GPIO bytes. Existing companion support and code-proven cursor addresses do not qualify native mouse gameplay. |
| Menu observation | [NativeReader](../../app/src/main/kotlin/com/pokedaisy/app/companion/data/NativeReader.kt#L1125) reads `inBattle` and matches controller pointers for action, move, bag, party and target, otherwise busy. It returns the first matching battler, and a failed battle flag read can collapse to no battle. [TelemetryStore](../../app/src/main/kotlin/com/pokedaisy/app/companion/TelemetryStore.kt#L179) and [engine fast telemetry](../../app/src/main/kotlin/com/pokedaisy/app/EmulatorEngine.kt#L1493) refresh on a cadence, with fast poll every 66 ms when applicable. | Derive a stricter observation including read validity, input readiness, active battler and exact cursors. Verify visible/ready gates around transitions, fade and animations on the reference ROM. |
| Target and cursor knowledge | [GameBattleInput](../../app/src/main/kotlin/com/pokedaisy/app/companion/GameBattleInput.kt), [BattleInput](../../app/src/main/kotlin/com/pokedaisy/app/companion/BattleInput.kt) and [cursor fixture tests](../../app/src/test/kotlin/com/pokedaisy/app/companion/data/BattleCursorTest.kt) encode menu actions and trusted cursor address leads. The tracked [FireRed rev 1 scripted fixture](../../app/src/test/resources/fixtures/firered_shiny_battle/README.txt) bytes show `inBattle=true`, battler 0 action handler `0x0802e44d`, zero action/move cursors and two battlers. A different [Emerald fixture](../../app/src/test/resources/fixtures/emerald_shiny_battle/README.txt) is in battle with a handler outside the known menu pointers. | The bytes verify decoding of those snapshots. Native FIGHT/BAG/POKéMON/RUN hit regions, move PP/type response, physical hover, and safe A/B timing are still open. |
| Companion execution | [BattleInputController](../../app/src/main/kotlin/com/pokedaisy/app/BattleInputController.kt#L784) includes cursor writes plus A, blind fallbacks, implicit open-FIGHT, double defaults and one-tap RUN handling. [Controller tests](../../app/src/test/kotlin/com/pokedaisy/app/BattleInputControllerTest.kt) pin those policies. | Reuse observations, `MenuCells`, `CoreKey` and frame-step patterns. A separate guarded intent producer must use normal buttons without cursor writes, blind walks, default targets or trailing confirmation. |

## Rendering and composition

| Area | Confirmed in source | Implication and remaining proof |
| --- | --- | --- |
| Game coordinates | [GameViewportView](../../app/src/main/kotlin/com/pokedaisy/app/GameViewportView.kt#L53) lays out emulator/DS children. [EmulatorView](../../app/src/main/kotlin/com/pokedaisy/app/EmulatorView.kt#L709) draws the shown wide quad and holds presentation geometry. Its game rect is unavailable in some wide/stretch modes and the core rect can be a HUD approximation. [WideCamera](../../app/src/main/kotlin/com/pokedaisy/app/WideCamera.kt) computes live window. The native [wide renderer](../../app/src/main/cpp/pk_wide.c) uses camera, tilemap, sprite and scene data. | Map through actual shown image and clip, including skip/hold cases. Presentation and requested camera values can differ. World projection requires independent renderer and map evidence. |
| Companion and HUD | [GameScreenView](../../app/src/main/kotlin/com/pokedaisy/app/GameScreenView.kt#L79) publishes frame/chrome exclusions. [SharedGameScreen](../../app/src/main/kotlin/com/pokedaisy/app/companion/ui/SharedGameScreen.kt#L119) animates panel placement and intercepts some taps. [SidePanelState](../../app/src/main/kotlin/com/pokedaisy/app/companion/ui/SidePanelState.kt#L21) shrinks the game only when docked. | Capture actual occlusion through panel animations and child windows. A target panel rectangle alone can be stale. Keep HUD and floating windows as independent owners. |
| DS and controls | [NdsBottomScreen](../../app/src/main/kotlin/com/pokedaisy/app/NdsBottomScreen.kt#L267) maps touches through its draw rect to native DS touch. The activity has focus and touch-inset integration. The debug mirror reserves width and changes layout. | Keep the two DS screen regions and native touch route distinct. Use the normal one-monitor layout for acceptance. See [WSA probe](WSA_PROBE.md). |

## Field, navigation and native non-battle UI

| Area | Confirmed in source | Implication and remaining proof |
| --- | --- | --- |
| Map geometry | [NativeReader](../../app/src/main/kotlin/com/pokedaisy/app/companion/data/NativeReader.kt#L401) validates map header/shape. [AreaMap](../../app/src/main/kotlin/com/pokedaisy/app/companion/data/AreaMap.kt#L107) groups and renders ROM warp-linked floors with fingerprinted tables. [Wide Snap](../../app/src/main/cpp/pk_wide.c#L502) captures raw VMap, camera and objects. [Metatile drawing](../../app/src/main/cpp/pk_wide.c#L719) masks tile IDs and uses rendering fallbacks. | Map visualization supplies structure. A movement graph needs verified elevation, terrain, directional edges, dynamic occupancy and context. Do not derive it from rendered tile IDs. |
| Player and NPCs | [NativeReader](../../app/src/main/kotlin/com/pokedaisy/app/companion/data/NativeReader.kt#L511) reads save-block location/facing with fallbacks. [Object scan](../../app/src/main/cpp/pk_wide.c#L303) knows live entries, current coordinates, facing and map/local IDs. [Ghost objects](../../app/src/main/cpp/pk_wide.c#L342) are render extrapolations. [Co-op presence](../../app/src/main/cpp/pk_wide.c#L4037) reads current/previous tile, partial motion and facing, with deliberate map lag. | Reuse proven live field/layout reads and reject stale identity. Verify step completion and eligible interaction side in ordinary gameplay. Ghosts and co-op interpolated coordinates cannot authorize a click. |
| Collision and field state | [Flight landing](../../app/src/main/cpp/pk_flight.c#L1115) calls profile-specific collision, elevation, behavior and occupancy queries. [ScenicFly](../../app/src/main/kotlin/com/pokedaisy/app/companion/data/ScenicFly.kt) has map placement and routing tuned to flight. [Read-only field observation](../../app/src/main/cpp/pk_wide.c#L4169) reports coarse lock/battle/text/window. Flight's [movement](../../app/src/main/cpp/pk_flight.h#L4) overrides normal field mechanics. | Flight landing can cross-check a decoder offline. It cannot establish legal walking edges. Idle, step, warp, battle, text, ledge and NPC blocking require their own tests. |
| Menus and prompts | [FfMenuWatch](../../app/src/main/kotlin/com/pokedaisy/app/companion/data/FfMenuWatch.kt#L100) uses learned callback changes. [ShopWatch](../../app/src/main/kotlin/com/pokedaisy/app/companion/data/ShopWatch.kt) and [MoveLearningWatch](../../app/src/main/kotlin/com/pokedaisy/app/companion/data/MoveLearningWatch.kt) cover specific coarse contexts. [Emerald co-op Start gate](../../app/src/main/cpp/pk_coop_field.c#L104) also verifies an active task. [GameSession](../../shared/src/commonMain/kotlin/com/pokedaisy/app/game/GameSession.kt) keeps field state across fades for existing features. | Collect native active menu, row, readiness and visibility independently. An Emerald battle fixture has `gMain+0x439 = 0x02`, consistent with the wide reader. The co-op gate uses `0x01`. Other co-op checks may still reject this frame. Treat as source inconsistency rather than a demonstrated gameplay regression. |
| Field commands and other engines | [GameField](../../app/src/main/kotlin/com/pokedaisy/app/companion/data/GameField.kt) holds flags. [GbField](../../app/src/main/kotlin/com/pokedaisy/app/companion/data/GbField.kt) and [Gen5Field](../../app/src/main/kotlin/com/pokedaisy/app/companion/data/Gen5Field.kt) contain engine-specific field support. [FieldItems](../../app/src/main/kotlin/com/pokedaisy/app/companion/data/FieldItems.kt) invokes game functions, and [PcMenuScript](../../app/src/main/kotlin/com/pokedaisy/app/companion/data/PcMenuScript.kt) arranges a scratch script. [Native DS field](../../app/src/main/cpp/nds/pk_nds_field.cpp#L917) reads DS map and process/task cues. | Treat convenience functions as instrumentation leads. NPC interaction, menu navigation and route execution use original buttons. Field flags alone cannot authorize dialogue advance or confirm on DS. |

## Build, fixtures and developer tooling

- [Upstream CI](../../.github/workflows/ci.yml) runs generated and translation guards, Android JVM suites and debug APK, host C API tests, desktop stress and docs checks. Proprietary-ROM coverage is gated separately by release infrastructure. [Release](../../.github/workflows/release.yml), [nightly](../../.github/workflows/nightly.yml) and [developer notes](../DEVELOPMENT.md#build) have distinct prerequisites.
- [Native capture](../../native-capture/README.md) offers deterministic mGBA frame stepping, core-key scripts, state and frame assertions. [Host core tests](../../app/src/main/cpp/test/CMakeLists.txt) use built diagnostic ROMs. [Fixtures](../../app/src/test/resources/fixtures) and the repository's JVM tests cover decoding and policy. Paparazzi and [Desktop preview](../../ui-preview/README.md) are visual tools with different hosts and input limits. Real WSA pointer dispatch still needs a probe.
- [Upstream agent notes](../../CLAUDE.md), the [ROM playbooks](../../.claude/skills/add-rom/SKILL.md) and [.claude launch config](../../.claude/launch.json) cover ROM mapping, fixture conventions, focused tests and preview. Reuse these with the fork's requirements and documented handoff.
- [LICENSE](../../LICENSE) and [NOTICE](../../NOTICE) identify the GPLv3 terms, required attribution and bundled component notices. Keep attribution in source, equivalent docs and app credits as applicable. See the fork's [build and distribution notes](DEVELOPMENT.md).
