## Phase 1B.2 WSA compatibility

Scope covers the ROM-free probe for `MS-INPUT-001` and its diagnostics. On the tested Windows 11 host, WSA `2407.40000.4.0` and Android 13 API 33 delivered physical pre-click hover, region transitions, distinct button identities and drag coordinates as `SOURCE_TOUCHSCREEN`/`TOOL_TYPE_FINGER`. All observed motion used the old alias 0. The old recorder rejected negative guest IDs and could also return 0 when the alias table filled. The traces contain no evidence of table exhaustion and do not preserve the exact ID or lookup result. The revised recorder aliases negative IDs within each session and records virtual, unregistered, or registered lookup status. That status does not establish physical device identity.

Before Phase 1B.2, crosshair and edge interpretation both depended on standard mouse recognition. Phase 1B.2 changed the crosshair to use raw coordinates independently. The explicit WSA profile needs corroborating touch-down and generic button-press evidence tied to a single contact. The historical build distinguished drag from click and deduplicated common release patterns. The independent review found ordering and cancellation counterexamples addressed by Phase 1B.4. Any guest ID can be shared by translated streams, so IDs alone never authorize a button gesture. Buttonless touches and ambiguous wheel-derived swipes retain their raw form. The Windows runner resolves its default build directory from the script body on PowerShell 5.1.
