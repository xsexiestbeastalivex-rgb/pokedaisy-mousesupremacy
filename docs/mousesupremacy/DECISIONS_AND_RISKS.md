# Technical decisions and risks

Headquarters set the platform, reference ROM, native-input, on-demand packaging and disposable experiment direction for this pass. The concrete designs and risk exits remain subject to Phase 0 review and later measurement.

| Decision | Proposal, evidence and consequence | Revisit when |
| --- | --- | --- |
| ADR-01 Android-native with WSA-first verification | Owner approved. Use standard Android input APIs as the baseline and the owner's existing WSA installation for primary development testing and runtime acceptance. Isolate WSA translation in its adapter. Reuse PokeDaisy touch, keyboard, controller and emulator input, with shared gameplay interactions available through the Android baseline. Keep stock physical controls as prerequisites for broader production compatibility and limit claims to tested targets. Native WSA wheel is optional. [Architecture](ARCHITECTURE.md#android-native-input-and-wsa-first-verification) · [WSA evidence](PROJECT_STATUS.md#phase-1b5-corrected-probe-physical-regression) | Add an emulator adapter only for a demonstrated compatibility difference. Review fallback if an essential WSA capability fails or the existing host becomes unavailable. Native SDL has a separate parity decision. [Fallback](WSA_PROBE.md#evidence-and-fallback-decisions) |
| ADR-02 Native input | Use coherent observations and original D-pad/A/B. The current companion controller uses more permissive one-tap, cursor-write and fallback policies. Pixel recognition can confirm visuals in tests, and a subtle overlay can indicate hover. Semantic readiness must still come from the game. | If ordinary input cannot reliably refresh the cursor, measure and review the availability of that capability and any optional hover-only feedback. Preserve the read-only observation and ordinary-input policy. |
| ADR-03 Shared boundary and compatibility | Reuse frame lifecycle and readers. Keep pure projection, hit testing and intents isolated from Android. Use exact English FireRed rev 1 first, with each capability qualified independently and narrow family overrides once evidence supports them. Broad best-effort matching and per-ROM duplicate engines carry greater verification and maintenance cost. | A second verified profile or frontend exposes a concrete shared-interface gap. |
| ADR-04 Movement | Start with A* or BFS on a verified local walking graph, then observe each ordinary step. Renderer/flight data can inform decoding. Direct coordinate writes and scripted flight bypass gameplay mechanics. | Evidence supports dynamic traversal edges, advanced terrain and multi-map routes. |
| ADR-05 Diagnostic surface | Reuse C host, capture scripts and ADB. Add bounded structured local tracing and a narrow dev-only interface on demand. A full server or MCP service would introduce unnecessary transport and security work at this stage. | Repeated tasks become impractical through scripts or local CLI. Evaluate the smallest integration. |
| ADR-06 Build identity | Use upstream's side-by-side `dev` variant and a disposable CI debug key for isolated experiments. Build on demand for the exact source commit. Require the save gate before game launch and approve persistent identity, signing, versioning and updater policy before retained installations. | Before retained installs, updater changes, distribution beyond test artifacts or long-lived development updates. |
| ADR-07 Shared semantics and enhanced Android touch | Separate conventional mouse, WSA and direct-touch adapters feed the same target, ownership, navigation and action engine. Opt-in touch-down highlights, eligible release confirms, and above-slop drag suppresses confirmation and navigates along an admitted axis. Preserve native wheel and ordinary touch, virtual controls, companion, DS, keyboard and controller behavior. [Owner refinement](https://github.com/xsexiestbeastalivex-rgb/pokedaisy-mousesupremacy/pull/2#issuecomment-7152221282) · [Gesture acceptance](specifications/05-semantic-interaction.md#direct-touch-and-drag) | Use real stock controls and qualified actual routing before production integration. Verify per-menu thresholds, clipping, bounds and native feedback before enabling each context. |
| ADR-08 Stateful defect prevention | Phase 1B treated callback counterexamples separately. Per-alias state and the tests lost sight of ordering after ownership ended. Future complex changes define cross-lifecycle invariants before implementation, select systematic tests by risk, and run an adversarial internal correction loop before independent acceptance. At the second material defect in a class, reassess the architecture and test the class. [Lifecycle and escalation](DEVELOPMENT.md#engineering-lifecycle) · [Method selection](TESTING.md#risk-based-verification) | New evidence challenges an invariant or exposes an oracle gap. Record the trigger, revised design, repeat verification and limits. |
| ADR-09 Personal fork and upstream synchronization | Owner approved. The independently maintained personal fork is the primary product. Prioritize approved functionality, usability and maintainability. Preserve Git history, modular changes, upstream reuse and automated compatibility regressions. Retain the Android-native baseline and WSA-first verification. Upstream contribution is optional. [Maintenance policy](DEVELOPMENT.md#fork-maintenance) | An upstream update changes a reused seam or breaks a pinned regression. Review and verify the sync before acceptance. |

| Risk | Evidence and impact | Mitigation and exit proof |
| --- | --- | --- |
| R1 WSA input delivery or routing diverges | The existing host delivered translated hover and identifiable button masks. Its native wheel axes were unavailable. The scoped replacement APK regression passed. | Independently re-review the corrected probe evidence. Prove stock controls and actual PokeDaisy routing separately. [ROM-free proof](WSA_PROBE.md) |
| R2 Native menu ready state is stale or misidentified | First matching handler, cadence and permissive fallback are insufficient to authorize a click. | Read a coherent same-boundary sample and prove stable cursor/readiness and distinct action edges on real ROM frames. |
| R3 Layout and compositor disagree | Actual shown quad can lag camera request or panel target placement. | Publish and test actual geometry, clipping and occlusion with visual evidence under resizing and frame hold. |
| R4 Key ownership leaks across transitions | Existing masks are combined/overwritten at different points. | Trace one owner, clear synthetic keys, test reset/rewind/fast-forward, pause, companion overlap and concurrent manual input. |
| R5 Walkability and NPC occupancy are incomplete | Raw draw maps and ghost sprites represent render facts. | Validate live traversal, local position/facing and movement completion before enabling each profile. |
| R6 Host build and signing drift | SDK/NDK, Gradle or native submodule requirements may block a checkout. CI debug signers can change. | Verify APK package/ABI/cert and pin source. Qualify the [save-isolation gate](DEVELOPMENT.md#pre-launch-save-isolation-gate) before any game launch. Approve and prove a persistent signer, identity, version and updater before retained updates. |
| R7 Subscriber CI permissions or forks trigger upstream workflows | Public fork ACL and inherited release/nightly/website defaults depend on repo settings. | Keep fork artifacts read-only and scoped. Review branch/CI rules, avoid inherited releases and check actual draft runs. |
| R8 Copyright or private session data reaches public CI | Native captures and saves can contain private/game data. | Use synthetic fixtures for CI and review shareable, bounded, redacted output. |
| R10 A dev launch writes the official save | GBA can resolve an override or an extra search folder. DS can use the ROM directory. | Read the actual save destination before launching. Verify the device gate with a separate original-side sentinel and a disposable shared-root rejection. |
| R9 Performance regressions under rapid hover | Game thread, viewport and companion share frame time. | Compare event-to-presented-cursor, frame pacing and resource cost against an unmodified matched run. |
| R11 Repeated fixes miss an ordering or ownership invariant | Phase 1B replay proved selected observed paths. Scenario tests missed a stale generation that first appeared after owner completion. | Require systematic per-step histories and independent oracle checks, and apply the [repeated-defect escalation](DEVELOPMENT.md#repeated-defect-escalation). |
