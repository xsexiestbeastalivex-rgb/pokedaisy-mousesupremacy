# Product requirements

The master initialization brief establishes the product requirements. The linked system specs are proposals for implementing them. Each spec supplies acceptance criteria and verification methods. Implementation and runtime evidence for all MouseSupremacy requirements are pending.

| ID | User-visible behavior and rationale | Dependencies and verification |
| --- | --- | --- |
| MS-INPUT-001 | A physical mouse can point, hover before any click, use its buttons and scroll. A configurable Mouse Mode uses left confirm/interact, right cancel, middle Start where applicable, and context-sensitive scrolling. | [Platform input](specifications/01-platform-input.md). Verify physical WSA plus Android frontend and normalization tests. |
| MS-ROUTE-001 | Game, HUD, companion and app chrome have exclusive event ownership. Manual keyboard/controller input takes precedence over mouse automation. Mouse Mode can be disabled with held inputs released. | [Ownership](specifications/02-input-ownership.md). Verify single dispatch and focus, resize and mode transitions. |
| MS-OBS-001 | The active ROM and its actual input-ready state govern mouse actions. | [Observation](specifications/03-game-observation.md). Verify invalid samples, loaded-state boundaries and exact reference frames. |
| MS-VIEW-001 | Hit regions follow the game picture through resizing, clipping, scale, letterbox, expansion, zoom and separate DS regions. | [Geometry](specifications/04-viewport-geometry.md). Verify round trips and visual registration against displayed frames. |
| MS-HIT-001 | Hover and clicks resolve to visible, eligible original actions. Clicking outside one performs no unrelated action. | [Semantics](specifications/05-semantic-interaction.md). Verify disabled, occluded, stale and boundary targets. |
| MS-BATTLE-001 | Hover follows native FIGHT, BAG, POKéMON and RUN, then move slots and native context info. Click accepts and right-click cancels where valid. Expand to targets, switches, items, catches, prompts and learning as verified. | [Battle](specifications/06-native-battle.md). Verify real state and native cursor across wild single battle and interruption scenarios. |
| MS-MENU-001 | Original menus support direct hover, click, back, context-sensitive scrolling and visible tabs. Covers title, Start, party, summary, bag, shops, PC, Pokédex, options and supported naming screens. | [Menus](specifications/07-native-menus.md). Test each separately per revision. |
| MS-DIALOGUE-001 | Dialogue and choices allow deliberate single advances or selections when the original screen accepts input. | [Dialogue](specifications/08-dialogue.md). Test text, prompt, transition and held-button behavior. |
| MS-MOVE-001 | Click a walkable tile and follow a valid route with original animation, collisions and encounters. New targets supersede the old route. Bad paths, manual input and scene changes stop or invalidate it. | [Navigation](specifications/09-overworld-navigation.md). Test grid and route logic, then controlled walking and interruption. |
| MS-NPC-001 | Hover identifies valid entities. A click routes to a verified adjacent tile, faces the entity, interacts and stops on the resulting scene. | [Entities](specifications/10-entity-interaction.md). Test moving and disappearing targets, signs, NPCs and decorative objects. |
| MS-COMPAT-001 | Exact, versioned profiles expose individually verified capabilities. Missing coverage results in no MouseSupremacy gameplay input for that context. | [Compatibility](specifications/11-compatibility.md). Test exact identity, capability declarations and safe rejection. |
| MS-FEEDBACK-001 | Keep original screens and native highlights where possible, plus optional subtle feedback. Preserve companion, HUD, touch, viewport changes and app settings. | [Companion and feedback](specifications/12-companion-feedback.md). Verify actual pixels, routing, keyboard/controller coexistence and Mouse Mode off. |
| MS-TEST-001 | Developers and agents can observe, exercise and replay failures with compact private diagnostics and reproducible scenarios. | [Diagnostics](specifications/13-diagnostics.md). Verify layer-specific evidence, bounded redacted capture and production isolation. |
